## 1. Two copies, and how a template reaches the running binary

The Go program embeds its templates from *inside* its own module; `//go:embed` cannot reach a
parent directory, so the Go tree must keep a physical copy. The copy is derived, not duplicated
by accident. The rule is:

- **Edit `docs/prompt-pack/templates/` only.**
- Run `node scripts/verify-prompt-pack.mjs --sync` to push the canonical files into the Go tree.
- Run `node scripts/verify-prompt-pack.mjs` (no flag) to prove every copy matches. It exits
  non-zero on drift, so it can be wired into a pre-commit hook or CI.

There are two delivery mechanisms, and neither is plain text in the shipped binary:

1. **Encoded blobs.** `floyd-go/scripts/obfuscate-prompts.mjs` gzips every `*.tpl` in
   `floyd-go/internal/agent/templates/` (level 9), base64-encodes it, and writes the map
   `encodedTemplates` into the generated file `floyd-go/internal/agent/templates_blob.go`
   (`// Code generated by scripts/obfuscate-prompts.mjs. DO NOT EDIT.`). `prompts.go` decodes
   those blobs once, in memory, at package initialisation via `mustDecodeTemplate`
   (`prompts.go:21-63`), which panics rather than running without a prompt layer. The blob map
   currently holds **9 entries**; `prompts.go` decodes 8 of them.
2. **Live `//go:embed` directives** for the `.md` description files:

```
floyd-go/internal/agent/agent.go:72               //go:embed templates/title.md
floyd-go/internal/agent/agent.go:75               //go:embed templates/summary.md
floyd-go/internal/agent/agent_tool.go:15          //go:embed templates/agent_tool.md
floyd-go/internal/agent/agentic_fetch_tool.go:19  //go:embed templates/agentic_fetch.md
floyd-go/internal/agent/agentic_fetch_tool.go:50  //go:embed templates/agentic_fetch_prompt.md.tpl
floyd-go/internal/agent/output_review.go:11       //go:embed templates/output_review.md
```

`agentic_fetch_prompt.md.tpl` appears in both mechanisms because the generator globs `*.tpl`; the
running code reads the `//go:embed` copy, not the blob.

The 2026-10-16 edition cited `prompt.go:31` for this struct and listed 12 fields; the struct has

guards them with `{{if}}`, so empty sections omit.

## 4. Which templates are actually rendered (there is no disk override)

**The override feature described in the 2026-10-16 edition no longer exists.** That edition
documented `promptTemplate(name, embedded)` reading `<global config dir>/prompts/<name>.md.tpl`
and replacing the embedded template at run time. The live function ignores its name argument and
touches no file:

```go
// floyd-go/internal/agent/prompts.go:67
func promptTemplate(_ string, embedded []byte) string {
    return string(embedded)
}
```

Consequently there is no runtime template override path: a file placed under
`<global config dir>/prompts/` is never read. Behaviour comes from the bundled standard plus
whatever project `MegaFloyd.md` the shared prompt loader discovers.
